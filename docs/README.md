## Keeping these true

Documentation that is wrong is worse than none, because the next session will trust it.

- The two files in `reference/` are generated by `npm run gen:db`. Never edit them by hand. A test fails if they drift.
- When you build a feature, change its mark in `02-product-spec.md` and tick it in `08-roadmap.md` in the same change.
- When you make a choice someone might later question, add an entry to `09-decisions.md`.
- When you finish a session, rewrite the top of `HANDOFF.md`. Do not append a diary; keep it a description of now.
- If you find a statement here that the code contradicts, the code is right. Fix the statement.
